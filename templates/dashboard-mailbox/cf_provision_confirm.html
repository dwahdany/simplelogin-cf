About the authorization
  • Sign in to the Cloudflare account that hosts this instance's mail worker. Cloudflare Email Routing can only deliver a zone's mail to a Worker in the same account, so {{ custom_domain.domain }}'s zone has to live in that account and you have to authorize with it. A different (for example personal) Cloudflare account cannot complete this — the run is refused before anything is written. Ask the operator which account that is if you are not sure.
  • You will approve this on Cloudflare's own consent screen. That screen has no zone picker: it authorizes the whole Cloudflare account you sign in with, not just {{ custom_domain.domain }}. We ask for the narrowest set of permissions the steps above need (zone, zone settings, DNS and email routing rules), but for the duration of this one run the authorization is account-wide. That is a Cloudflare limitation, and it is why the authorization is thrown away immediately.
  • It is never stored. The access token exists only inside the request that comes back from Cloudflare; it is not written to our database, and no part of it survives the run.
  • It cannot be renewed. We deliberately do not ask for offline access, so Cloudflare issues no refresh token — the authorization expires by itself within about an hour even if everything else goes wrong.
  • It is revoked as soon as the run finishes, whether the run succeeded or failed: the access token is handed back to Cloudflare's revocation endpoint before you see the result. Cloudflare may still list this app under Manage Account > Authorized apps — that entry is the record of your approval, not a live key, and you can remove it there. Removing it changes nothing here, because we store nothing.
  • Every run asks again. There is no "remember me" here by design.

  • Safe to run again at any time: every step is checked before it is written, so steps already done are skipped.
