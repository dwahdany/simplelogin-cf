{# DKIM needs NOTHING from the user on this deployment, so this section asks for nothing and can never "fail". Upstream SimpleLogin runs its own Postfix and signs every domain's outbound mail with ONE key, so a custom domain CNAMEs its dkim._domainkey at SimpleLogin's. That model does not exist here: src/lib/dkim.ts dkimSignOutbound signs only when the From domain is EMAIL_DOMAIN or an ALIAS_DOMAINS member (isOwnEmailDomain), so a custom domain's mail is NEVER signed with our key. Its DKIM comes from Cloudflare Email Sending, which signs with Cloudflare's own per-domain keys once the operator onboards the domain — and adds whatever records that needs itself. So the old CNAME table asked the user to publish OUR public key for THEIR domain, where it would sign nothing, and then flagged the (correctly) absent records as "Your DNS is not correctly set". dkim_verified is informational only — nothing in the mail path reads it (grep: only src/lib/rows.ts). #}
